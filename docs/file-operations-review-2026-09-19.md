# 文件操作专项检查（1.1.78）

本轮从用户发现的“替换选项缺失、跳过结果不清楚”继续检查复制、移动、删除、撤销、重做、批量重命名和压缩工具交接。检查包括源代码、独立临时目录上的故障注入、原生参数解析和真实 WinUI 交互。不是全产品渗透测试，也不代表所有功能都已完善。

## 参考其他软件的处理方式

- [Directory Opus 冲突处理](https://www.gpsoft.com.au/help/opus12/Documents/The_Replace_Dialog.htm)：明确区分替换、跳过和其他冲突选择。FilesMate 已有替换、跳过、保留两者；文件夹合并后内部文件的冲突继续询问。同一文件不能替换自身，链接和类型不同的项目也不能直接覆盖，界面应解释原因。
- [Directory Opus 错误列表](https://www.gpsoft.com.au/help/opus11/documents/Unattended_operation.htm)：保留失败列表并提供后续查看、重试和导出。此次先补齐不会被刷新清除的结果和完整失败详情；尚未实现任务队列及按失败项重试。
- [FreeCommander 删除](https://freecommander.com/fchelpxe/en/Delete.html)：显示选中的删除目标，区分送入回收站和永久删除。删除不能因为没有选择而悄悄改为删除正在浏览的文件夹。
- [Microsoft SHFileOperation](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shfileoperationa)：返回成功不能单独证明没有取消，必须检查 `fAnyOperationsAborted`。
- [Microsoft 参数解析规则](https://learn.microsoft.com/en-us/cpp/c-language/parsing-c-command-line-arguments?view=msvc-170)：引号前的反斜杠需要正确转义，不能只把路径包在双引号中。

## 本轮修复

| 级别 | 确认的问题 | 修改和验证 |
| --- | --- | --- |
| 高：误操作 | 回收命令在没有选中项目时使用当前文件夹作为目标；背景菜单存在可执行入口。 | 命令启用条件和执行入口都要求选中项目。菜单、工具栏、快捷键测试以及真实 UI 中的无选择删除测试确认不会调用底层删除。 |
| 高：恢复可靠性 | 多文件循环改名的撤销中途失败，原来的单步回滚会被其他项目占据的原名称挡住，并吞掉恢复异常。 | 先把已发布目标撤回各自临时路径，再恢复原名称；无法恢复时报告保留文件路径。旧代码在三个故障注入用例中失败两个，新代码全部恢复名称和内容，历史保持可重试。 |
| 中：结果误判 | 系统回收取消被当作正常返回；部分删除后出错会丢失已完成部分的撤销记录。 | 取消明确抛出取消信号，检查仍存在的项目；删除入口在 finally 中记录已移除项目并刷新。测试覆盖成功返回但文件仍在、取消后不推进历史，以及部分完成后可撤销。 |
| 中：反馈缺失 | 粘贴/拖放只报告第一个失败，跳过和取消缺少汇总；提前筛选拖入项目可直接静默返回。状态栏消息还会被刷新覆盖。 | 统一完成/跳过/失败/取消汇总。拖放交给共同的传输边界验证并生成结果。异常结果使用可关闭的非模态通知，失败详情可以展开和选择复制。暂存架和双栏传输使用同一套汇总。 |
| 中：输入验证 | 回收站 `$I` 元数据忽略声明长度并按文件剩余大小分配，未知版本和相对路径也可能被接受。 | 只接受已支持的版本，限制至 Windows 路径大小，验证记录长度、终止符及绝对路径。覆盖畸形记录、超大记录、旧格式、新格式和实际回收/恢复。 |
| 中：兼容性 | 压缩工具参数简单加引号，空格路径末尾的反斜杠可能吞掉结束引号，改变参数边界。 | 复用统一 Windows 参数转义实现，使用原生 `CommandLineToArgvW` 验证路径及目标参数完整往返。 |
| 性能 | 传输前去除重复的父子选择采用两两比较，N 个选中项目需要接近 N² 次比较。 | 改为路径规范化、集合去重和父目录查找，工作量取决于项目数和路径深度；保留原顺序。测试覆盖 20,000 个同级项目及父子选择。未据此宣称整体内存或吞吐有固定百分比改善。 |

新增用户文案和更新说明包含中文、英语、日语。没有加入常驻轮询、监控守护进程或自动覆盖行为。

## 仍需继续完善的部分

1. **传输任务管理**：普通粘贴尚无完整的字节进度、暂停、队列和仅重试失败项功能。大文件的单次系统复制结束前，取消无法立即中断，不能把按文件的进度当成按字节进度。
2. **撤销的事务边界**：循环改名回滚已修复，但包含多个系统回收/恢复或替换步骤的一次撤销，不是跨文件的原子事务。部分系统操作被取消、进程崩溃或磁盘断开时仍可能需要人工处理。历史目前仅在会话内；普通撤销仍同步执行，耗时恢复可能影响界面响应。后续应统一任务执行和持久化恢复日志，而不是添加自动重试覆盖。
3. **外部组件信任范围**：解压由安装的 CompactMate 执行，参数交接检查不能代替对其解压路径、符号链接、压缩炸弹和可执行文件发现策略的审计。Office 预览进程也仍不是操作系统安全沙箱，详见之前的 security-review 文档。
4. **长时间/外部环境验证**：本轮没有覆盖真实断电、所有网络共享、所有 ACL、恶意进程同时改写文件系统、不同 Windows 账户隔离或长期内存稳定性。测试通过不能替代这些验证。
