# FilesMate 批量重命名调研与设计建议

日期：2026-09-16。状态：调研与设计，尚未实施以下新版交互。调研期间用户报告 Office 预览空白，先修复该回归问题。

## 结论

建议采用“常用操作直接可选 + 可组合规则 + 实时对照 + 整批撤销”。默认保护扩展名，只处理用户选中的项目。高级规则按需展开，不让第一次使用的人先理解正则或模板语法。

## 官方产品资料

| 产品 | 已核实的做法 | FilesMate 可借鉴的部分 |
| --- | --- | --- |
| [Finder](https://support.apple.com/guide/mac-help/rename-files-folders-and-disks-on-mac-mchlp1144/mac) | 批量入口提供替换文本、添加文本、格式三类操作 | 第一层选择应当简明，按任务表达 |
| [PowerRename](https://learn.microsoft.com/en-us/windows/powertoys/powerrename) | 即时改名前后对照、逐项勾选、正则、名称/扩展名作用范围、编号、撤销 | 用户执行前能核对每一项；高级能力不挤占基础操作 |
| [Advanced Renamer](https://www.advancedrenamer.com/user_guide/methods) | 多个方法依列表顺序应用 | 可添加、停用、调整规则顺序，解释处理先后 |
| [Advanced Renamer 冲突处理](https://www.advancedrenamer.com/user_guide/name_collision_rules) | 默认拒绝冲突，也可追加编号或按规则另取名称 | 默认阻止重名；自动避让必须先出现在预览里 |
| [Advanced Renamer 撤销](https://www.advancedrenamer.com/user_guide/undo_batch) | 批次历史、逐项结果与可选撤销；源文件发生变化时可能失败 | 撤销要可追溯，并如实报告无法恢复的项目 |
| [Bulk Rename Utility](https://www.bulkrenameutility.co.uk/) | 文本处理、编号、日期、元数据、保存规则、列表映射、预览和日志 | 常用规则可保存；粘贴名称列表适合课程、资料等有明确命名清单的场景 |

以上为官方文档调研，未对这些软件做同机性能跑分，不把官网性能宣传作为实测结果。

## 当前代码的实际状态

现有功能有基础骨架，不必从零重写：多选 F2 和右键可进入批量入口，核心层已有替换、前后缀、编号、正则和大小写字段。但界面只提供查找、替换两项。

代码核查范围：

- `src/FilesMate.App/Views/BatchRenameDialog.xaml` 与 `.xaml.cs`：每次输入同步生成预览，使用 ScrollViewer + ItemsControl；没有逐项状态或虚拟化。
- `src/FilesMate.Core/Operations/BatchRenamePlanner.cs`：固定规则顺序；规划时同步调用 Path.Exists；正则没有超时；对文件夹也按扩展名拆分。
- `src/FilesMate.Core/Operations/BatchRenamePlan.cs`：忽略大小写比较使仅修改字母大小写的操作被当成无变化。
- `src/FilesMate.Platform.Windows/Operations/WindowsBatchRenameExecutor.cs`：已有临时名两阶段执行；失败后尽力回滚，但吞掉回滚错误，CompletedSources 也没有表达回滚后的实际状态。不能称为原子事务。
- `src/FilesMate.Core/Operations/FileUndoStack.cs`：32 条内存撤销记录；不是跨重启的批次日志。
- `src/FilesMate.App/Views/PaneFileActions.cs`：无效规则在对话框关闭后才显示首个错误。应把问题留在编辑界面就地解决。

## 建议的界面流程

1. 多选文件或文件夹，按 F2 / 右键“批量重命名”。
2. 左侧选择操作，右侧展示“原名称 → 新名称 → 状态”。初始按文件列表当前显示顺序生成固定快照。
3. 每改一项规则即更新预览。差异高亮，未变更项目淡化；可筛选“有变化”“有问题”。筛选不改变编号顺序。
4. 可取消某个项目的勾选；重新编号的影响立即展示。第一版约定：编号仅包含勾选项目，按当前明确的处理顺序连续分配。
5. 底部固定显示“将修改 N 项 · 不变 M 项 · 冲突 K 项”。没有变化或还有未解决冲突时，执行按钮不可用，并明确说明原因。
6. 按“重命名 N 项”开始。结束展示成功、未处理、失败项目及原因，支持整批撤销。

建议采用可调整大小的窗口，跟随浅色/深色和主题色；预览区占主要空间。窄窗口可上下排布规则和预览，底部操作区不随内容滚走。长文件名可横向查看、悬浮查看完整名称，不能仅用省略号隐藏关键差异。键盘能够完成选择规则、编辑、筛选和执行。

## 第一版应做扎实的能力

| 操作 | 具体交互 |
| --- | --- |
| 查找替换 | 是否区分大小写、替换全部/首次、可选正则；错误直接显示在输入框附近 |
| 添加文字 | 前缀、后缀、指定位置；后缀默认位于扩展名前 |
| 统一名称与编号 | 基础名称、起始值、步长、位数、分隔符、编号位置；例“历史真题_001.pdf” |
| 清理名称 | 去首尾空白、合并连续空格、删除指定文本、按位置删除；中文和 emoji 按用户看到的字符处理 |
| 大小写 | 单独选择作用于名称或扩展名；仅大小写变化也可以执行和撤销 |
| 插入信息 | 用按钮插入父文件夹名、修改日期、原名称、序号，无需手写变量语法 |
| 组合与预设 | 多条规则按顺序应用、开关单条规则、保存/载入/删除自己的预设 |
| 个别修正 | 允许为少数行手动填写目标名称，并明确标记该行覆盖规则结果 |

文件与文件夹混选时，文件夹始终把整个名称作为名称处理，不能把“课程.第一章”的“.第一章”当成扩展名。文件默认只保护最后一段扩展名；对 `.tar.gz` 等组合扩展名提供明确规则或后续支持，不偷偷改变拆分约定。

后续优先考虑“从 Excel 粘贴多行名称”：先显示顺序对应关系，数量不匹配时阻止执行。再评估 EXIF 拍摄日期、音频标签和递归子目录。首版不加入任意脚本执行，也不把移动/复制混进重命名流程。

## 重名、执行、撤销

- 批次内相同目标需要标记所有相关行；已有同名文件默认阻止，不覆盖。用户主动选择“自动追加编号”后才生成避让名称，并重新预览。
- 命名校验包含非法字符、控制字符、设备保留名、尾随空格/句点、空名称，以及目标文件系统支持的路径长度。不能把所有路径统一按 260 字符判断。依据：[Windows 文件命名规则](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)。
- 默认遵循普通 Windows 目录的名称比较规则；对启用区分大小写的目录需识别能力或明确限制，不把所有磁盘、共享目录假定为完全相同。
- 执行前重新检查文件身份及目标占用，处理“预览后文件被别人移动/删除/新增”的变化。
- 使用临时名处理名称交换、循环与仅大小写变化；执行日志记录每项实际所在路径。不能把多个文件重命名包装成文件系统原子事务。
- 中途失败时尝试恢复；如果恢复也失败，保留日志并列出当前路径和恢复方法，不能只报最初错误。
- 撤销也要重新验证文件身份和占用情况，不覆盖之后由其他程序创建的文件。跨重启恢复由有上限的批次日志支持；保留时长/数量后续确定。
- 第一版不同时处理父目录和它的后代路径；遇到这种输入要解释并要求拆批。默认不递归、不跟随目录链接。

## 性能与功能联动

- 名称变换为可取消的后台计算；输入合并更新，旧结果不能覆盖新结果。正则有超时，不能卡住输入。
- 文件存在性/元数据检查在后台完成并控制并发，尤其是网络盘。只有规则用到的元数据才读取；不为了预览名称加载文件内容、缩略图、Office 或 WebView。
- 列表虚拟化，只创建屏幕附近的行；仅维护路径、名称、状态等必要数据。关闭窗口释放预览列表和后台任务。
- 编号顺序明确且稳定，自然排序下 `第2课` 应在 `第10课` 前；规则计算与筛选不能暗中重排。
- 成功后统一通知文件列表、搜索索引、标签、收藏、暂存架、打开的文件夹标签页和预览。需逐一核查各功能是否按文件身份或路径关联；不能仅刷新当前列表就算完成。
- 文件系统监视事件合并处理，避免每改一个文件就重建一次列表、丢掉选中状态。

## 验收场景

1. 下载资料去共同前缀，PDF 扩展名不变；未匹配项目不执行空操作。
2. 视频按自然顺序编号，先预览，勾选排除和筛选的规则清楚。
3. 大小写转换、中文、emoji、多点名称、带点目录正确。
4. 两文件交换名称、三文件循环、同批重复、外部重名、执行期间目标被占用。
5. 只读/权限不足/网络盘离线、中途取消、某一步失败、回滚再失败与重启恢复。
6. 整批撤销后名称正确；原位置被其他文件占用时不会覆盖。
7. 1,000 与 10,000 项分别记录预览耗时、输入响应、内存峰值和关闭后残留；这是待测项目，不是已达到的性能承诺。
8. 深浅主题、高 DPI、窄窗口、键盘操作、长名称、错误状态与执行按钮均可读可用。

## 实施顺序

先修正纯大小写、命名校验和失败状态模型；再做虚拟化实时预览与常用规则；最后加入预设、持久撤销和跨功能联动。每一阶段都以可预览、可解释、可恢复为验收标准。
