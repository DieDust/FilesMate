# Surface materials

FilesMate uses a system backdrop beneath its main window. Layered chrome, sidebar and file content retain their own neutral palette. Settings and the shelf use `FrostedBackdrop`, a desktop-sampling `SystemBackdropElement` with a shared neutral tint. Context menus and tag submenus use `FlyoutBase.SystemBackdrop` with the same tint. These compositor materials are created only while visible and released when closed. Text and controls are never faded as a whole.

Microsoft recommends avoiding overlapping background Acrylic layers and notes the GPU cost of large Acrylic areas: [Acrylic](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic). [Mica](https://learn.microsoft.com/en-us/windows/apps/design/style/mica) is an efficient wallpaper-derived, opaque foundation. The existing Mica option remains available; FilesMate does not implement continuous screenshots or a custom per-frame blur.

`GlassMaterialPolicy` defines a continuous strength curve: `curve = (1 - strength)^1.35`. The shared file-area foundation retains `0.30 + 0.70 * curve` neutral coverage. Sidebar, command bar and file content use equal `0.40 + 0.60 * curve` coverage over that foundation. Equal transmission prevents a common background color from changing their relative contrast. Their combined background transmission is about 15% at 50% strength, 29% at 73%, and 42% at maximum strength. Floating surfaces use the equivalent combined coverage, so they do not expose much more wallpaper than the shell. At 0% all are opaque. Unified layout keeps its continuous chrome design.

Layered tints also compensate for contrast lost during alpha compositing: `tint = neutral + (original - neutral) / coverage`, clamped to a byte. The dark anchor is the file-area neutral; the light anchor is white to avoid clipping highlights. All calculations start from the original palette, never a previously compensated tint. This keeps sidebar/content channel differences within one display level of the opaque palette over the same background, instead of letting those differences shrink with alpha. Settings navigation and cards use the same compensation. This does not remove all background color or guarantee identical colors over different parts of a wallpaper; it bounds background influence while preserving glass. It adds only brush updates when appearance changes, with no extra blur surface or per-frame work.

Do not substitute an in-app `AcrylicBrush` for a desktop material: [in-app Acrylic](https://learn.microsoft.com/en-us/windows/apps/develop/ui/in-app-acrylic) samples app content, not the desktop. This substitution made Settings look opaque even when its tint was reduced. Actual compositor captures over a controlled colorful background must show distinct results at 0%, 50% and 100%; RenderTargetBitmap alone cannot prove desktop transparency. Activate the window before capturing, since inactive Acrylic can use its fallback.

`ShellStyleResources` updates shared brush instances in place when appearance changes. High-contrast dictionaries are not overwritten. Windows manages Acrylic fallback for unsupported or restricted composition states. At zero transparency or with glass disabled, desktop backdrops are removed. SearchHost uses `DWMSBT_TRANSIENTWINDOW` with the same strength policy and neutral palette; DWM rounds both its backdrop and frame instead of combining a separate custom window region with an independently drawn backdrop.

Check Light and Dark at 0%, 1%, 25%, 50% and 100%; switch Layered / Unified repeatedly; inspect Settings, shelf, menus, dialogs and search. Compare over both colorful and neutral backgrounds. The UI-only `FILESMATE_SHELL_TRANSPARENCY_SMOKE` hook checks brush consistency, composited palette contrast, tint round trips, slider persistence, opaque-mode backdrop removal and shelf spacing; it is excluded from production builds.
