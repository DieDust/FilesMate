## Checks performed

- 35 profile/ordinary-mode/undo regression tests and five replacement-backup budget tests passed: 40 passed, zero failed and zero skipped. This is the tested subset; a full solution regression pass is not claimed.
- The actual portable ZIP preview worker passed five isolated XLS cases: PNG/JPEG and nested images, the 24-picture limit, malformed raster fallback, cells-only input, truncated-file failure and a successful subsequent preview. It used the production 384 MiB job limit and 15-second timeout; fixture inputs were unchanged.
- The extracted portable app started, displayed demonstration files and closed normally. Two portable directories used different search hosts; closing the first app stopped its host and left the second intact. Existing installed app/search processes remained alive, and installed settings metadata and relevant registry values were unchanged.
- The update manifest passed RSA-PSS/SHA-256 verification with the product public key. Version, installer size and SHA-256 matched. All three localized notes decoded as UTF-8 with no replacement characters.
- The existing update server's public HTTPS installer and portable ZIP were each downloaded in full and matched the same sizes and SHA-256 hashes. The published [signed update manifest](https://47.97.117.111/filesmate/preview/latest.json) is byte-for-byte identical to the locally signature-verified envelope and points to 1.1.210.0. Normal TLS certificate validation remained enabled.
- GitHub's uploaded asset sizes and SHA-256 digests matched the verified local files. The current README screenshot was captured from the actual extracted portable app using demonstration files.

No installer was run and no installed application or user settings were replaced for these checks.

## Known dependency risk

NPOI 2.7.6 retains SixLabors.ImageSharp 2.1.11. This version has three High and two Moderate advisories:

- [GHSA-j3p4-wp97-rph4](https://github.com/advisories/GHSA-j3p4-wp97-rph4): unsafe histogram indexing.
- [GHSA-j9gm-c75j-xc9q](https://github.com/advisories/GHSA-j9gm-c75j-xc9q): TIFF CCITT T4 bounds access.
- [GHSA-jjfr-hcj7-qf5w](https://github.com/advisories/GHSA-jjfr-hcj7-qf5w): TIFF CCITT T6 bounds access.
- [GHSA-gwg2-r3hj-4w44](https://github.com/advisories/GHSA-gwg2-r3hj-4w44): excessive ICC CLUT allocation.
- [GHSA-wmxv-xphr-5c9g](https://github.com/advisories/GHSA-wmxv-xphr-5c9g): a BigTIFF non-progressing loop.

These vulnerabilities are not fixed by this release. The release owner accepted deferring the dependency upgrade. NuGet audit remains enabled, the five warnings stay visible, and the packaging opt-in rejects other package versions or advisory findings. Both packages include `KNOWN-DEPENDENCY-RISKS.json`. Process resource limits do not make Office or image parsing an OS security sandbox.

## Remaining limitations

Expanding large recursive trees and fast scrolling can still cause noticeable delays; this release does not claim that performance issue is fixed.

Permanent deletion remains non-undoable. Native Windows transfers still have the previously documented FilesMate undo limitations. Portable ZIP updates are manual and retain the adjacent `data` folder.
