## 搜索实验

先运行用户提供的 Python 脚本，复现两组精确匹配缺失，以及十万行中查询 `zz` 触发十万次匹配函数。随后用实际 `NameIndexReader` 与 SQLite 包测试新代码。

下表来自本机合成数据库：每十个文件名中一个为 `学习_编号.txt`，其余为 `report_编号.txt`；每个查询十次。P95 使用最近秩法，包含首次调用，没有控制机器上的其他应用。结果用于确认行为和成本，不代表所有真实目录、硬盘或网络环境。

| 行数 | 查询 | 实际复核的文件名数 | 中位耗时 | P95 |
|---|---|---:|---:|---:|
| 100,000 | `zz` | 0 | 0.84 ms | 7.58 ms |
| 100,000 | `学习` | 10,000 | 18.36 ms | 21.18 ms |
| 100,000 | `report_00000001.txt` | 200 | 8.87 ms | 9.78 ms |
| 100,000 | `r` | 90,000 | 75.12 ms | 126.12 ms |
| 1,000,000 | `zz` | 0 | 0.75 ms | 7.47 ms |
| 1,000,000 | `学习` | 100,000 | 137.84 ms | 153.84 ms |
| 1,000,000 | `report_00000001.txt` | 290 | 45.77 ms | 46.62 ms |
| 1,000,000 | `r` | 900,000 | 583.35 ms | 766.74 ms |

十万行数据库从约 5.77 MiB 增至 11.90 MiB，新增索引耗时 1.13 秒；百万行从约 57.59 MiB 增至 106.19 MiB，耗时 9.64 秒。这是与无子串索引的表比较，不能当成与旧 trigram 索引的增幅。文件名长度与重复程度会影响空间。

20 ms 后请求取消高频词查询，十万行在约 34 ms、百万行在约 37 ms 返回取消。仅为本机观测，不能作为硬时限。

已有 schema 2 索引仍可读取，精确匹配漏项修复立即生效。短词索引需要重建：启用自动刷新时现有升级逻辑会安排重建，关闭自动刷新时需在搜索设置中手动重建。

## 明确保留的限制

撤销快照上限为 4,096 个对象和 128 层；链接、不可读取或无法获得文件标识的对象会使校验拒绝操作并保留文件。元数据与文件标识无法证明文件内容完全未变，也不能完全消除校验后被外部程序抢先修改的竞态。没有全量内容哈希。替换批次和原有文件操作仍可能部分完成，完整持久化恢复日志需后续设计。

1.1.85 的 `CopyFileEx` 仅覆盖复制过程取消。后续 [1.1.86 复核](2026-09-22-index-and-file-safety.md) 已补上普通及替换传输的跨卷移动取消，并验证源身份、只读、备用数据流及源删除失败恢复。底层设备阻塞仍无固定时限取消保证；字节进度尚未统一到所有入口。

Office Job 是资源限额，未改变转换程序的用户权限。安装的第三方原生 Office/COM 预览、Shell 扩展和 WebView2 不在这个受管转换 Job 的完整权限边界内；低权限沙箱、实际解压读取/像素/嵌套预算和更全面的畸形文件语料仍待单独验证。
